# RoF2 campsite support

The catalogue contains the basic campsite (description41678) and all596 paid campsite descriptions shipped in the matching RoF2 `dbstr_us.txt`. All71 paid kit families and required lumber names match existing itemtype58 item definitions. Each paid creation consumes one kit and one lumber bundle. Native catalogue row IDs are supplied by the server: description IDs are stable emulator catalogue IDs, not claimed recovered historical Live campsite IDs. Display names combine the kit family and lumber name.

Category IDs follow the matching client's `Resources/campsitecategories.txt`:1General,2SpellFocus,3MeleeFocus,4Statistics,5Resistances,6Illusions,7Buffs. The native list parser receives count followed by usability, kit ID, description ID and name; unsupported or currently unusable rows cannot be created even if a client forges a request.

## Recovered behavior and explicit emulation policies

Numeric stat/focus maximums and spell-level ceilings come directly from the native descriptions. All304 numeric and melee campsite definitions project through27 matching native Standard buff templates. Effective caster levels are derived so the native primary formula exactly equals each description or authorized melee tier value. Full12-slot SPA/base/limit/max/formula and duration/song signatures are checked against the matching client data before enabling creation. The real buff is the sole authority for server bonuses and client stat display; no parallel manual stat addition remains. Native stat caps, stacking rules, haste and damage-shield signs follow the ordinary spell engine. The pulse refuses to overwrite or erase an ordinary buff. Focus uses the described maximum deterministically, competes with the existing spell-focus contribution, and retains ordinary item/AA stacking. Exact Live random distributions and recipe-to-effective-level selection beyond explicit numeric description matching were not recovered. Native buff stacking is used for numeric/melee projections.

Descriptions for Cleave, Ferocity, Sharpshooting, Evasion and Prevention omit numeric magnitudes. Matching shipped spells7354..7358 independently establish native SPAs169/177/184/174/175, formula coefficients6/1/1/3/2, and maximum48/8/8/24/16. Cleave targets precisely skills0,1,2,3,8,10,26,28,30,36,74,77; Sharpshooting targets7and51; Prevention modifies parry, not block. The authorized emulator policy treats the eight yellow lumber tiers Elm/Alder/Maple/Ash/Fir/Briarwood/Oak/Teak as effective caster levels1..8 for these formulas. That recipe-to-level mapping is a policy, not a recovered Live mapping. Other shipped Standard spell formulas show that a universal lumber ordinal mapping would be incorrect.

Illusion campsites extract only the illusion appearance from the matching native Standard templates7372..7399and7601..7606, including their exact race/heritage/texture parameters. They do not cast the unrelated stat/run-speed effects in some templates. Normal illusion buffs and the player's illusion block take precedence; exiting a campsite restores the prior appearance without removing another caster's buff. Gear updates do not become ownership of a permanent campsite illusion.

Faerune uses existing native Standard spell7616, checked for SeeInvisible1/UltraVision1/WaterBreathing1. DeadManFloating uses existing Standard spell7617, checked for WaterBreathing2/SeeInvisible1/Levitate2/PoisonResistance20. A two-tick heartbeat lease marked with a reserved campsite caster name permits exact source cleanup on exit without fading ordinary buffs of the same ID. These scoped leases are excluded from saved buffs and any legacy marked row is ignored before load normalization; eligible camps recast them from authoritative location on relog. No fictional fellowship spell IDs are introduced.

The official EverQuest February6,2007 fellowship announcement establishes three nearby members, one campfire per fellowship and one-hour lifetime: https://www.everquest.com/news/imported-eq-enus-50327 . It does not establish a numeric aura radius. The default100-unit spherical radius is an explicit configurable emulator policy (`SetFellowshipCampsiteRadius`), not asserted Live parity.

## Inventory and runtime safety

Paid creation runs both exact material debits and campsite persistence on one dedicated, nonretry database transaction. The active authenticated inventory admission epoch/token/process/client/zone/instance is checked under row lock. Pending custody/coin/house transitions reject the operation. Exact raw inventory/null/custom/GUID identity is rechecked independently of the current runtime item pointer/serial/projection. A loaded runtime serial is not substituted for the legacy persisted GUID.

All validation completes before either material debit. The transaction guard serializes concurrent campsite creation, and the second creator cannot consume a second set of materials. A connection identity and active transaction check surrounds the debit callback and precedes COMMIT; connection failures never reconnect inside the transaction. Only a successful commit applies the corresponding in-memory decrement with database writes disabled. Uncertain commit or a postcommit runtime mismatch rejects further profile writes and disconnects the session for authoritative reload.

World visuals restore from persistent zone/instance/expiry state. Cached membership, visuals and effective bonuses reconcile every five seconds; mutation invalidation expedites reconciliation. Membership, connection/alive state, expiry and spherical distance are checked before applying a focus. Stats and support leases update on the aura heartbeat. Database failure removes effect authority rather than treating stale cached membership as current.

Standalone catalogue/effect/sanitizer and real-database material rollback/concurrency tests live outside emulator source in the analysis workspace. Passing them establishes implementation behavior, not physical gameplay or full historical Live equivalence.

## Native stat projection validation

The first physical paid-HP check exposed a missing client projection: the server-only manual HP field did not cause a native buff and was not the FlatMaxHPChange field used by Client::CalcMaxHP. Health description41586 now uses existing Standard of Health 7607 at caster level 2; its slot11 SPA69 with formula75 produces150 HP on both native and server calculation paths. Resource tiers150..1500/1575/1650 correspond to effective levels2,4,..20/21/22. Standard regen, stat, resist, haste and damage-shield levels are derived independently from their own primary formulas. These levels are validated for every numeric/melee catalogue record, not assumed equal to lumber ordinal.

Numeric and melee leases share the existing reserved caster marker and two-tick heartbeat, exclude persistence, preserve ordinary buffs with the same IDs and clean up on leaving range or destroying a camp. SaveBuffs skips these leases in the actual serialization loop as well as the sizing pass; LoadBuffs rejects legacy marked rows before caster-name normalization. Adding or removing a lease recalculates normal bonuses (which includes HP/mana/endurance maxima) and sends resource updates.

Both initial application and heartbeat refresh send the native `OP_Buff` duration projection with the derived effective caster level. This is necessary for the client to compute the same primary formula as the server; a server-side value alone is insufficient. The 27 numeric/melee templates are7354..7371and7607..7615. Complete12-slot and duration/song signatures are checked, and an altered/missing template refuses new creation/projection. Preflight checks ordinary buffs before casting: neither a stronger nor weaker ordinary buff is overwritten to install the campsite lease. A conflict can leave a valid campsite without that member receiving its numeric buff until the conflict ends. Focus camps retain the explicit manual maximum policy because native focus templates use random/minimum behavior that would change that policy.

The combined source passed compilation and was deployed with a supervised restart. The matching native client repeat measured maxHP2374 to2524 and server2671 to2821, then returned to2374 on destruction. Native Faerune application/removal, barbarian appearance/accelerated expiry restoration, category filtering, camp world model and insignia return were also observed. Detailed screenshots and acceptance results are retained outside production source in the completion analysis directory. None of the projection changes establishes exact Live recipe-to-level, focus-distribution or radius equivalence.
